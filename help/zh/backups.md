# 历史保留 {#retention}

栏目 **数据与备份**（数据库图标）。每次轮询都会保存流量、错误和端口状态。为避免数据库无限增长：

| 数据 | 默认 | 之后 |
|---|---|---|
| 详细历史（每次轮询） | 7 天 | 汇总为每小时数值（平均值和最大值） |
| 每小时历史 | 365 天 | 删除 |
| 事件 | 90 天 | 删除 |

数据库维护每小时自动运行。**立即执行维护** 可马上启动；**压缩数据库文件** 可在删除旧数据后释放磁盘空间。

# 备份 {#backups}

- **每日自动备份**——每天一次；保留 **保留备份数** 中设置的数量（默认 14），更早的会被删除。
- **创建备份**——手动创建，例如在大改动之前。
- 以下情况也会自动备份：新版本启动且数据库结构有变化时，以及恢复其他备份之前。

每个备份都可以 **下载**、**恢复** 或 **删除**。**从文件恢复** 可上传之前下载的或在其他服务器上创建的备份。

> **重要：** 备份与数据库位于同一磁盘（数据文件夹中的 `backups` 文件夹）。请定期下载或将该文件夹复制到其他服务器——与数据库放在一起的备份无法抵御磁盘故障。

加密密钥（`switchmap.secret` 文件）**不包含** 在备份中——因此备份可以安全地保存和传输。但没有这个文件，备份中的 SNMPv3、邮件、Telegram 和 NetBox 密码需要重新输入。请将 `switchmap.secret` 另行妥善保存。

# 恢复 {#restore}

点击所需备份旁的 **恢复**。当前数据库会先保存为单独的备份（“恢复前”），因此可以通过恢复该备份来撤销此次恢复。如果备份中没有用户，用户及其密码不会被回滚。

# 迁移到其他服务器 {#move}

1. 在旧服务器上停止 SwitchMap。
2. 从数据文件夹中复制 `switches.db` 和 `switchmap.secret`。
3. 在新服务器上安装 SwitchMap，停止服务，将文件放入其数据文件夹，然后启动服务。

数据文件夹的位置见[安装与配置](/help/installation#files)。

# 变更日志 {#audit}

**变更日志** 栏目（时钟图标）显示谁在何时改了什么：交换机、连接、设置、用户以及失败的登录尝试。可按交换机和类型筛选。

交换机变更旁的 **撤销** 可恢复之前的值。已删除的交换机可以连同其连接和设备一起 **恢复**。
