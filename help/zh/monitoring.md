# 定期轮询 {#polling}

打开 **设置**（菜单底部的齿轮），开启 **定期通过 SNMP 轮询交换机**。SwitchMap 会按所选间隔轮询所有设有 IP 地址的交换机。

| 间隔 | 适用场景 |
|---|---|
| 1–2 分钟 | 小型网络，需要精细图表 |
| 5 分钟 | 几乎所有人 |
| 10–15 分钟 | 数百台交换机或低速链路 |

不开启定期轮询时，只能通过交换机页面上的 **通过 SNMP 轮询** 按钮更新数据。

**端口名称、描述和 VLAN**——多久读取一次很少变化的数据：端口名称与描述、VLAN、LLDP 邻居（用于拓扑）。

| 模式 | 适用场景 |
|---|---|
| 每次轮询 | 网络正在建设、扩展或维修——变化立即可见 |
| 每小时一次 | 网络稳定——对交换机的请求几乎减少一半，交换机 CPU 负载更低 |

两种模式下，端口状态、流量、错误和 MAC 地址都会在每次轮询时读取。交换机页面上的 **通过 SNMP 轮询** 按钮始终读取全部数据——在交换机上做了更改后点击它即可，无需等待一小时。

# 监测内容 {#metrics}

- **端口状态**——有无链路。状态变化会产生“端口断开”或“端口恢复”事件。
- **利用率**——流量速率占端口速率的百分比。根据两次轮询之间的计数器差值计算，因此从第二次轮询起才会出现。
- **错误**——自上次轮询以来累计的收发错误数。
- **CPU、内存、温度**——如果交换机通过 SNMP 报告（取决于厂商）。
- **PoE**——各端口功耗，如果交换机支持 POWER-ETHERNET-MIB。

# 告警阈值 {#thresholds}

在 **设置 → 告警阈值** 中：

| 阈值 | 事件 |
|---|---|
| 端口利用率，% | 流量超过端口速率的此百分比 |
| 两次轮询之间的端口错误数 | 错误在增加——通常是线缆问题 |
| CPU 负载，% | 交换机 CPU 过载 |
| 温度，°C | 过热 |

超过阈值时产生一个事件，恢复正常时再产生一个。**0** 表示关闭该阈值。如果交换机停止响应，“交换机不可达”事件会说明它是否仍能 ping 通（若能，问题在 SNMP 设置），还是 ping 不通（问题在网络或电源）。

# 图表 {#charts}

在交换机页面点击 **统计** 打开图表：

- 任意端口的流量速率（入站和出站）；
- 交换机的 CPU、内存和温度。

时间段从 1 小时到 1 年。较长时间段使用每小时数据，因此图表加载很快。历史保留多久——见[数据与备份](/help/backups#retention)。

# 事件 {#events}

所有事件都显示在顶部栏的铃铛中以及首页的 **告警** 列中。要通过 Telegram 或邮件接收，请配置[通知](/help/notifications)。
