通知报告的事件与铃铛中看到的相同：交换机不可达、端口断开、利用率过高、错误、过热。在 **通知** 页面配置（纸飞机图标，仅管理员）。

> **重要：** 只有在轮询交换机时才会产生事件。请在 **设置** 中开启 **定期轮询**，否则不会有任何可通知的内容。

# Telegram {#telegram}

1. 在 Telegram 中打开 **@BotFather**，发送 `/newbot` 并为机器人命名。BotFather 会回复形如 `123456789:AAH…` 的 **令牌**——将其粘贴到 **机器人令牌**。
2. 给您的机器人发送任意消息（例如 `/start`）。如果是群组——将机器人加入群组并在群里发一条消息。
3. 点击 **查找聊天** 并添加需要的聊天。也可以手动输入聊天 ID：群组 ID 以负号开头。
4. 启用该渠道，选择事件并点击 **保存**。**发送测试消息** 可检查是否一切正常。

SwitchMap 服务器需要通过 HTTPS 访问 `api.telegram.org`。如果通过代理访问互联网，请在 **HTTP 代理** 中填写（`http://proxy:3128` 或 `http://登录名:密码@proxy:3128`）。

# 邮件 {#email}

1. 点击您的邮件服务按钮——服务器、端口和加密方式会自动填入。企业邮箱请自行填写。
2. **登录名** 通常是邮箱地址。**应用专用密码**——见下文。
3. **收件人**——一个或多个地址，用逗号分隔。
4. 点击 **发送测试邮件**，然后点击 **保存**。

| 端口 | 加密 |
|---|---|
| 465 | SSL |
| 587 | STARTTLS |
| 25 | 无（仅限内部服务器） |

> **重要：** Gmail、Yandex、Mail.ru 和 Outlook 不接受普通邮箱密码。请在邮箱安全设置中创建 **应用专用密码** 并使用它。

# 避免消息过多 {#filters}

| 设置 | 作用 |
|---|---|
| 选择事件 | 例如只要“交换机不可达”和“端口断开” |
| 恢复通知 | 是否通知“端口恢复”“恢复可达” |
| 仅重要端口 | 只包括在交换机上有描述、在示意图上有连接或为中继的端口——不含用户电脑 |
| 静默时段 | 夜间只发送关键事件 |
| 端口抖动 | 一小时内多次断开和恢复的端口只发一条警告，而不是几十条消息 |

同一次轮询的多个事件会合并为一条消息。如果网络或 Telegram 不可用，消息会稍后发送——SwitchMap 会不断重试。旧事件（超过一天）不会补发——它们保存在事件日志中。
